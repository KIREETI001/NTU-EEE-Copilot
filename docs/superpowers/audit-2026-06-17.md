## §1 — Data layer ⚠️

- **Schema enforcement ❌** — `rulebook/schema/` has no contents; the compiler hardcodes
  `.filter(d => d !== "schema")` for a dir that's empty. Nothing validates the YAML.
- **Provenance per-leaf ⚠️** — provenance is per-*section* `confidence` + a per-*file* `sources`
  list (meta.yaml). Individual leaf facts do NOT carry their own `source`+date. The
  "fail if any fact lacks both" script does not exist.
- **136 vs 137 🔒** — internal category sum `83+17+15+21 = 136` ✅ (verified by build + read);
  resolving 136-vs-137 needs the intranet AU-summary PDF (you must supply).
- **Biomedical `unverified` ✅** — correctly tagged (specializations.yaml:146).
- **Renumbered codes ✅** — rulebook uses current `EE4523`/`EE4323`/`EE4227`; old codes appear
  only in `change_flag` notes.
- **Liability facts ✅(internal)** — quota 24 / sub-cap 12, FYP `EE4080` + internship `EE3279`
  ineligible, A→P / F→NR, branch date `2026-01-01` all present and self-consistent across
  grading.yaml + tests. External attestation vs the official FGO circular still needs the doc.
- **Internal consistency ⚠️** — category sum ✅, honours bands contiguous/non-overlapping ✅,
  GPA scale A+→F complete ✅. BUT same code → divergent titles across specs (no course master).
- **Compiler determinism ⚠️** — content IDENTICAL across two builds; the ONLY variance is
  `generated_at` (build-rulebook.mjs:49). That single line makes the determinism and
  `git diff --exit-code` staleness gates always fail; committed JSON is otherwise current.

**Fixes:** add a JSON Schema + validate in CI; drop/derive `generated_at`; add a per-leaf
provenance linter; introduce a canonical `courses` table keyed by code.

## §2 — Engine ⚠️ (math solid; surface untested)

- **Purity ✅** — no file I/O outside `rulebook.py` (grep clean).
- **Coverage 73%** — cgpa 91 / fgo 89 / honours 100 / specialization 92 / models 100, but
  **`main.py` 0%** (no endpoint tests). Untested branches: unknown-grade ValueError,
  code-not-found block, quota-exhausted suggest, non-GPA outcomes.
- **★ Real oracle 🔒** — `test_golden_cgpa_anchor` is synthetic and mislabeled (asserts 4.05,
  docstring says 3.74). Needs your real Degree Audit rows to become a true oracle.
- **FGO enforcement ⚠️** — ineligible *categories* (FYP/INTERNSHIP/SANCTIONED) are blocked and
  tested ✅; BUT block is category-only (`_is_ineligible`, fgo.py:59) and the rulebook
  classifies the actual ineligible courses under CORE/FC → **a by-code guard is needed**
  (HIGH finding #1). Total + sub-cap enforced ✅. Pass-not-counting-to-floor/spec encoded ✅.
- **Input validation ⚠️** — negative AU / bad category rejected by Pydantic (422) ✅; unknown
  grade, duplicate codes, unknown fyp_grade → uncaught **500**; rejection paths untested.
- **Determinism of suggest ✅** — `candidates.sort(reverse=True)` includes code as tiebreaker.
- **Dependency health ⚠️** — real transitive advisory: `starlette 0.41.3` (fastapi 0.115.6);
  no engine venv → pip-audit polluted by global torch/pillow/tornado (NOT engine deps).
- **CORS ✅(dev)** — scoped to `localhost:3000`; tighten for prod.
- **One-rule violation** — `honours.py:25` hardcodes the grade order instead of deriving from
  `gpa_scale`.

**Fixes:** add by-code FGO guard + test; add endpoint tests + map ValueError→422; reject dup
codes; derive grade order from rulebook; isolate a venv + bump fastapi (pulls patched starlette).

## §8 — Deployment ⚠️ (decision)

- Explorer is static-hostable. `/optimizer` needs the engine, and per the §5 review the engine
  must be **private + proxied** — so the optimizer **cannot** ship to a pure static host.
- **Recommendation:** explorer on a static/edge host; engine deployed **private** behind the
  authenticated same-origin proxy; until then `/optimizer` stays **local-only**.
- `ENGINE_URL` must be server-env-configured (today it defaults to `localhost:8000` via the
  to-be-removed `NEXT_PUBLIC_ENGINE_URL`); tighten CORS to the real origin.
